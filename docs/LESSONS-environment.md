# 作業環境の事故（全プロジェクト共通）

コンペや案件の種類によらず起こる事故と、その回避策です。いずれも実際に起こしたものだけを
載せています。新しいプロジェクトを始めるとき、または環境を触る作業の前に読んでください。

**自動修正ツールに、コマンド出力から組み立てたファイルリストを渡さない。**
`ruff check --fix $files`（`$files` は別コマンドの出力）でファイルシステム全体が走査され、
164,154 ファイルが書き換わった。システムの Python 標準ライブラリ、10 の仮想環境（うち他
プロジェクトの 4 つが実害。稼働中の取引ボットを含む）、apt と pip が管理するパッケージが
壊れ、復旧に数時間かかった。明示パスを渡す。実行前に必ず件数を確認する。

**稼働中サービスの仮想環境を再構築しない。** 実行中プロセスの共有ライブラリを差し替えると
SIGSEGV で落ちる。停止 → 修復 → 起動の順にする。

**復旧時は「最新を入れる」ではなく「依存が満たされる版を入れる」。** 最新版の numpy を入れて
numba が起動不能になった。

> 出典: 2026-08-06 に実際に起こした事故。被害は 164,154 ファイル、システムの Python
> 標準ライブラリと 10 の仮想環境（稼働中の取引ボットを含む）に及び、復旧に数時間かかった。
